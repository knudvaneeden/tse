# asm2bin

`asm2bin.s` is a TSE SAL external macro that converts a marked block of
16-bit x86 assembly instructions into hexadecimal byte values suitable for
use in a SAL inline binary procedure.

The current version is **1.1.0.0.3**.

The original 1995 macro used the DOS `DEBUG.EXE` program. That program is no
longer normally available on 64-bit Windows. This updated version uses NASM
and NDISASM instead.

## Requirements

- The SemWare Editor (TSE) for Windows.
- The TSE SAL compiler `sc32.exe`.
- NASM at:

  ```text
  G:\CYGWIN\bin\nasm.exe
  ```

- NDISASM at:

  ```text
  G:\CYGWIN\bin\ndisasm.exe
  ```

`nasm.exe` and `ndisasm.exe` normally belong to the same NASM installation.

## What the macro does

The macro performs these steps:

1. Copies the marked assembly source to a temporary buffer.
2. Adds `BITS 16` and `ORG 0x100` for NASM.
3. Converts DOS DEBUG-style hexadecimal operands to NASM syntax.
4. Runs NASM to produce a flat 16-bit binary file.
5. Runs NDISASM to disassemble the generated binary.
6. Converts each instruction into SAL hexadecimal byte values.
7. Inserts the resulting lines after the assembly source in the current file.
8. Removes its temporary files after successful completion.

## Compile the macro

Open a command prompt in the directory containing `asm2bin.s` and run:

```bat
sc32 asm2bin.s
```

The source should compile without errors. Load the resulting external macro in
TSE using your normal macro-loading method or restart TSE if the macro is
already configured to load automatically.

When replacing an older version, make sure the newly compiled macro is loaded.
If TSE displays `Error reading debug.out`, the original DEBUG-based macro is
still loaded. Reload the new macro or restart TSE.

## How to use it

1. Open a file containing 16-bit x86 assembly instructions in TSE.
2. Mark the instructions as a line block or character block.
3. Do not use a column block.
4. Press **Alt+F11**.
5. Wait for the final TSE warning reporting how many instructions were
   inserted.
6. The generated hexadecimal lines appear after the original assembly block.

The macro can also be started through the TSE Potpourri or macro menu if it is
loaded without using the **Alt+F11** key assignment.

## Example

Mark this assembly source:

```asm
mov  ax,dada
push ax
mov  ax,1100
int  2f
pop  dx
retf
```

The updated macro accepts the original DOS DEBUG convention in which bare
numbers are hexadecimal. Internally it converts the operands as follows:

```text
dada  -> 0xdada
1100  -> 0x1100
2f    -> 0x2f
```

The inserted result is similar to:

```text
  0xB8  0xDA  0xDA                 // :0100 mov ax,0xdada
  0x50                              // :0103 push ax
  0xB8  0x00  0x11                 // :0104 mov ax,0x1100
  0xCD  0x2F                       // :0107 int 0x2f
  0x5A                              // :0109 pop dx
  0xCB                              // :010A retf
```

The exact spacing may vary, but the generated byte values and addresses should
be equivalent.

## Supported number syntax

The macro automatically converts bare hexadecimal operands from the original
DEBUG syntax:

```asm
mov ax,dada
mov ax,1100
int 2f
```

NASM-style hexadecimal notation can also be used directly:

```asm
mov ax,0xdada
mov ax,0x1100
int 0x2f
```

Semicolon comments are preserved and are not altered by the hexadecimal
conversion.

## Important limitations

- The generated code is assembled in **16-bit mode**.
- The origin is fixed at hexadecimal address `0100`.
- Only line blocks and character blocks are supported.
- Column blocks are rejected.
- The marked source must be valid NASM assembly after the automatic hexadecimal
  conversion.
- Symbolic labels made entirely from hexadecimal characters can be interpreted
  as hexadecimal values because the original DEBUG syntax did not support
  normal symbolic labels in the same way as NASM.
- The configured NASM and NDISASM paths must exist.

## Troubleshooting

### `Error reading debug.out`

The old 1995 macro is still running. Compile the updated `asm2bin.s`, reload the
new compiled macro, or restart TSE.

### `NASM failed`

The warning displays the name of a temporary diagnostics file. Open that file
in TSE to see NASM's error message.

Check that this file exists:

```text
G:\CYGWIN\bin\nasm.exe
```

Also verify that the marked source contains valid 16-bit NASM instructions.

### The NASM diagnostics file is empty

Make sure you are using version **1.1.0.0.3** or newer. Version 1.1.0.0.2
incorrectly interpreted the successful Boolean result returned by TSE SAL's
`Dos()` function as a failure.

### `NDISASM failed`

Check that this file exists:

```text
G:\CYGWIN\bin\ndisasm.exe
```

### No output is inserted

- Confirm that a line or character block is marked.
- Confirm that the newly compiled macro is loaded.
- Check the NASM diagnostics file named in the final warning.
- Test the six-instruction example from this document.
