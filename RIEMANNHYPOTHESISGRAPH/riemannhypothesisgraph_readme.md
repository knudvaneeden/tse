# Riemann Hypothesis Graph — version 1.0.0.0.9

## Dark theme from first browser paint

**Version 1.0.0.0.9:** When PowerShell generates the HTML, it writes the validated `.ini` theme directly on the root `<html>` element. The CSS colors are therefore selected before the page is displayed, eliminating the initial light-mode flash. `theme=dark` remains the default, `theme=light` remains supported, and the in-browser switch still works. Existing generated HTML must be regenerated by running the macro. No new launcher or worker files are added.

## Non-blocking background calculations

Compile `riemannhypothesisgraph.s` with `sc32 riemannhypothesisgraph.s`, and run the compiled macro in TSE. After the last `Ask()` input, SAL invokes `cmd.exe /d /c start "" /min powershell.exe ...` directly using `Dos()`; the PowerShell computation runs independently while TSE returns to editing. There are **no extra launcher or worker files**.

**Version 1.0.0.0.7 correction:** TSE `Dos()` returns a nonzero value to indicate that its invocation succeeded, and zero on failure. It does **not** return the Windows process exit status directly. The old check `if resultI <> 0` incorrectly displayed an error on success. The corrected check is `if NOT resultI`. `_RETURN_CODE_` enables independent command-exit information from `DosIOResult()`; a successful asynchronous launch does not mean that calculation has already finished. TSE's status message means only that the launch command was invoked.

The PowerShell script writes these output files next to the `.mac`:

- `riemannhypothesisgraph_status.txt`: RUNNING, COMPLETED, or FAILED with timestamps and output paths.
- `riemannhypothesisgraph.log`: calculation diagnostics and progress.
- `riemannhypothesisgraph.html`: finished graph (only current when status is COMPLETED).
- `riemannhypothesisgraph_data.json`: numerical graph data.
- `riemannhypothesisgraph_output.txt`: output manifest.

The browser opens when calculation finishes if `open_browser=1`. Do not run overlapping jobs from the same macro directory, as output paths are shared.

**Distribution:** five files (`.s`, `.ps1`, `.ini`, `_template.html`, `_readme.md`) next to the compiled `.mac`.

**Testing:** SAL compile and CMD launch behavior still need confirmation under Windows/TSE 4.50.33. The source fix follows documented `Dos()` return semantics.

# Riemann Hypothesis Graph — version 1.0.0.0.9

## What changed

The PRIMARY graph is now the **complex image plane** `w = zeta(s)`, rather than contour levels in the `s`-plane. The program evaluates the Riemann zeta function numerically at a rectangular input grid, then draws the actual mapped images of selected input lines: fixed `Re(s)` with varying `Im(s)`, and fixed `Im(s)` with varying `Re(s)`. These lines produce smooth curved, overlapping figures reminiscent of the supplied illustrations. Color families distinguish the two coordinate-line families. The mapped critical line `Re(s)=1/2` is additionally drawn as a dashed curve, computed separately at **exactly** `Re(s)=0.5` (not at the nearest sampled grid column). A boxed **input s-plane inset** on the default image graph shows the **straight vertical line** at `Re(s)=0.5`, with trivial and detected non-trivial zero markers. These are two different coordinate planes and must not be conflated. Sampled curves are numerical approximations, not traced exact analytic solutions.

**Important geometric distinction:** the image graph's axes are `Re(zeta(s))` and `Im(zeta(s))`, not `Re(s)` and `Im(s)`. ALL zeros are mapped to the origin `w=0`, so the mapped graph cannot individually mark trivial zeros at `s=-2,-4,-6` or the non-trivial zero heights. Click **Domain contours + zeros** to see these points at their actual input-plane positions. The extra **3D magnitude surface** remains available.

Light/dark is a `.ini` parameter, `theme=dark` by default, and can also be switched in the browser.

## New .ini parameters

```ini
[graph]
theme=dark
default_view=image
image_real_min=-3.5
image_real_max=3.5
image_imag_min=-3.5
image_imag_max=3.5
image_sigma_lines=15
image_t_lines=13
image_line_width=1.5
```

The image-plane coordinate limits allow zooming into the loops. `image_sigma_lines` and `image_t_lines` select 2 to 32 smooth curves from the underlying sampling grid. The graph preserves equal scale on both image axes so mathematically circular structures are not artificially stretched. Increasing `real_samples` and `imag_samples` smooths curves but makes PowerShell computation slower.

## Installation

Compile `riemannhypothesisgraph.s` with `sc32 riemannhypothesisgraph.s` (TSE Pro 4.50.x) and run the compiled macro. Keep `.mac`, `.ini`, `.ps1`, and `_template.html` together; resources and generated HTML/JSON/output manifest are resolved beside the `.mac` via `CurrMacroFilename()`, not `CurrDir()`. TSE SAL `Ask()` uses `_EDIT_HISTORY_`; the last values are saved back to the `.ini`.

PowerShell 5.1 and a modern HTML5 browser are required. No external plotting packages or network access are needed. To run manually: `powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\riemannhypothesisgraph.ps1 -IniPath .\riemannhypothesisgraph.ini`.

## Caveats

The zeta function is meromorphic and has a pole at `s=1`, which is skipped in the data. Numerical continuation is Euler–Maclaurin with configurable summation/correction terms; it is not a rigorous proof or an exhaustive search of the zeros. The Riemann Hypothesis is not established by any of these visualizations.

# Riemann Hypothesis Graph — version 1.0.0.0.9

## Purpose

Visualize the Riemann zeta function over a **finite portion of the complex plane**, including the negative real half-plane and its **trivial zeros** at s = -2, -4, -6, ... . The graph also shows the **critical line** Re(s)=1/2 and the non-trivial zeros **numerically detected on that line**. The Riemann Hypothesis asserts that *all* non-trivial zeros are on the critical line; drawing the line or identifying some zeros does **not** prove the hypothesis.

Since zeta(s) is complex-valued, the 3D display shows the **magnitude** |zeta(s)| (height), with real and imaginary parts of s along the horizontal axes. The magnitude is clipped at a user-configured height; zeta has a pole at s=1.

## Included files

- `riemannhypothesisgraph.s` — TSE SAL front end, version 1.0.0.0.9
- `riemannhypothesisgraph.ini` — sample parameters, version 1.0.0.0.9
- `riemannhypothesisgraph.ps1` — built-in .NET complex-number Euler–Maclaurin numerical evaluator, version 1.0.0.0.9
- `riemannhypothesisgraph_template.html` — offline interactive canvas renderer, version 1.0.0.0.9
- `riemannhypothesisgraph_readme.md` — documentation, version 1.0.0.0.9

## Requirements

- TSE Pro Windows 4.50.x, SAL compiler `sc32.exe`
- Windows PowerShell 5.1 or compatible, .NET with `System.Numerics.Complex`
- Modern browser with HTML5 Canvas and JavaScript (no browser extension, network access or Plotly dependency)

## Installation and running from TSE

1. Extract all ZIP contents into one writable folder (for example `F:\BBC\TAAL\RIEMANNHYPOTHESISGRAPH\`).
2. Compile using `sc32 riemannhypothesisgraph.s` in that folder (or TSE's SAL compile command).
3. Keep `riemannhypothesisgraph.mac`, `.ini`, `.ps1` and `_template.html` in the **same folder**.
4. Execute `riemannhypothesisgraph.mac` in TSE. Answer the `Ask()` questions. The program uses `_EDIT_HISTORY_` and remembers the last values in `.ini`.
5. TSE calls `cmd.exe /d /c start "" /min powershell.exe ...` directly; CMD returns after starting PowerShell, leaving the editor available. PowerShell calculates and optionally opens the browser when done. No separate CMD launcher or PowerShell worker is required.

Alternatively run PowerShell directly:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File ".\riemannhypothesisgraph.ps1" -IniPath ".\riemannhypothesisgraph.ini"
```

When running directly, PowerShell uses the directory containing the supplied INI for output. Under normal TSE operation this is the directory containing the compiled `.mac`, determined via `CurrMacroFilename()` — **not `CurrDir()`**.

## Outputs (always full paths, beside the `.ini` / `.mac`)

- `riemannhypothesisgraph.html` — interactive, standalone HTML graph containing calculated data.
- `riemannhypothesisgraph_data.json` — generated data: sampled magnitude surface, markers and critical-line slice.
- `riemannhypothesisgraph_output.txt` — complete generated output paths, parameters/zero counts and timestamp.

The program overwrites these three generated files on each successful run. `riemannhypothesisgraph_status.txt` records RUNNING, COMPLETED or FAILED, full output paths and a timestamp. The browser opens when completed if `open_browser=1`.

## Default parameters in `.ini`

| Name | Default | Meaning |
|---|---:|---|
| real_min | -6 | Left real-axis bound; shows trivial zeros -2,-4,-6 |
| real_max | 2 | Right real-axis bound |
| imag_min | 0 | Lower imaginary-axis bound; includes real axis |
| imag_max | 35 | Upper imaginary-axis bound; normally includes first five non-trivial zeros |
| real_samples | 49 | Surface samples along Re(s) |
| imag_samples | 71 | Surface samples along Im(s) |
| height_cap | 8 | Maximum displayed magnitude |
| open_browser | 1 | 1: auto-open browser; 0: write files only |
| summation_terms | 100 | Euler–Maclaurin initial terms |
| correction_terms | 10 | Euler–Maclaurin corrections (1–10) |
| zero_search_step | 0.25 | Numerical critical-line zero search increment |

Several settings can also be edited in TSE `Ask()` prompts. All settings can be edited directly in the INI. For larger imaginary-axis values, increase `summation_terms`; complex-plane numerical evaluation may otherwise become inaccurate.

## Graph interactions

- Mouse drag: rotate the 3D surface.
- Mouse wheel: zoom.
- Reset view: restore initial camera.
- Toggle surface / Toggle zeros: simplify the view to locate lines and zero markers.
- The smaller graph below the legend shows |zeta(1/2 + it)| versus t.

The yellow line is the **critical line on the floor** (Re(s)=1/2), and the pink markers represent candidate zeros found numerically along that line. Green markers identify the trivial zeros along the negative real axis.

## Numerical and mathematical limitations

- Analytic continuation uses the Euler–Maclaurin formula with finite terms, rather than the ordinary Dirichlet series alone. It is an *approximation*, not a validated/rigorous interval calculation.
- The numerical zero search minimizes the magnitude along the critical line and accepts small residuals. These are approximate critical-line zeros; it does not search the entire critical strip for off-line zeros.
- The window cannot cover the entire infinite complex plane. The sampling may hide narrow features and the pole is capped.
- Accuracy for very negative real parts, large imaginary parts and close to the pole may deteriorate. Increase the summation count or use specialist arbitrary-precision mathematical libraries for research-grade numerical work.
- No claim is made that all non-trivial zeros have been found, or that all such zeros lie on the critical line.

## Background execution (new in version 1.0.0.0.9)

The TSE SAL macro uses the built-in Windows CMD `start` command directly, without the
`.cmd` launcher and `_worker.ps1` of version 1.0.0.0.5:

```cmd
cmd.exe /d /c start "" /min powershell.exe -NoProfile -NonInteractive -ExecutionPolicy Bypass -File "C:\FULL\PATH\riemannhypothesisgraph.ps1"
```

The empty `""` is mandatory as the START window title. PowerShell automatically finds the
`.ini` beside the `.ps1`; no INI path argument is needed. The command runs asynchronously,
so TSE should become available as soon as CMD starts PowerShell. The new status text file
is written by the main PowerShell script, without an extra worker file.

The `Dos()` return code reports whether TSE invoked the command, not the Windows exit code. A START launch result does not guarantee the calculation succeeded. Inspect
`riemannhypothesisgraph_status.txt` and the PowerShell console for calculation failures.
If Windows execution policies or file permissions prevent execution, check the FAILED
status or run the PowerShell script in a visible shell for diagnostics. The `start`
command is Windows CMD syntax and is not a separate `.exe`.
