** INTEGERS and FLOATING POINT **

TSE SAL is strict 32 bits.
So the maximum positive integer value is 2^31 - 1 = 2147483647.
So the maximum negative integer value is -2^31 - 1 = -2147483647.
If larger integer values are necessary then implement your own big integer operations.

TSE SAL does not know LONG integers.

TSE SAL does not supply floating point out of the box.

Based on our technical deep dives and previous adjustments to TSE SAL
(The Semware Editor Macro Language) scripts, here are the essential
syntax rules and constraints to keep in mind for development:

### Core Functionality & Logic

* **Buffer Management:** Use `AbandonFile()` instead of
                         `AbandonBuffer()`, as the latter is not a
                         valid function in the TSE SAL environment.

* **Variable Handling:** When a function expects a buffer variable as
                         the first parameter, pass the **name of the
                         variable as a string** rather than the
                         variable's value.

* **Arithmetic Operators:** The `%` symbol is not defined for modulo
                            operations. Always use the `MOD` keyword
                            instead.

### Data Types & Limits

* **Integer Constraints:** TSE SAL operates on 31-bit signed integers.
                           For any calculations requiring values
                           greater than $2^{31} - 1$, you must
                           implement custom big integer logic.

* **Floating Point:** The language does not natively support
                      floating-point calculations or decimal types. All
                      logic must be handled via integer math or string
                      manipulation.

### Best Practices for Macro Development

* **State Persistence:** Always verify if a buffer is "hidden" or
                         "system" before performing mass edits to avoid
                         interfering with the editor's internal state.

* **String Precision:** Since math is integer-only, use string
                        functions like `SubStr()` and `Val()` for any
                        "pseudo-decimal" displays (e.g., treating the
                        last two digits of an integer as cents).

---

**Data Types & Constants**
- TSE SAL has no floating point - only `INTEGER` and `STRING`.
- `constant` only works for numeric values. String constants must be declared as global string variables, e.g. `string NAMES_FILE[255] = "c:\\temp\\p022_names.txt"`.
- Maximum string length in TSE SAL is 255 characters (`string s[255]`).

---

**Reserved Words - Never use as variable or proc names**
`Val`, `Left`, `Right`, `Up`, `Down`, `Word`, `Line`, `Mark`, `Block`, `Find`, `Replace`, `File`, `Buffer`, `Window`, `Menu`, `Key`, `Help`, `Exit`, `Quit`, `Next`, `Prev`, `First`, `Last`, `Top`, `Bottom`, `Insert`, `Delete`, `Copy`, `Move`, `Goto`, `Jump`, `Set`, `Get`, `Put`, `Read`, `Write`, `Open`, `Close`, `Create`, `Destroy`, `Show`, `Hide`, `Enable`, `Disable`, `Check`, `List`, `Sort`, `Search`, `Select`, `Run`, `Exec`, `Load`, `Save`, `Print`, `Pos`, `Version`.

**CRITICAL**: `Val` and `Pos` are the most commonly misused - always substitute (e.g. `nVal`, `idx`).

---

**Syntax**

- Bit shifts: `shl`/`shr` (not `<<`/`>>`).
- Bitwise operators: `^` for XOR, `&` for AND, `|` for OR, `~` for NOT.
- `NOT` is **bitwise**, not logical: `NOT 0 = -1`, `NOT 1 = -2`. Never use `NOT x` as a logical test. Use `x == 0` or `x == FALSE`. Never write `while NOT done` - use `while done == FALSE`.
- `Format` zero-padding: `Format(value:width:"0")` - e.g. `Format(n:5:"0")`. Not C-style.
- TSE SAL can only display ASCII 0-255.

---

**Integers & Arithmetic**
- `Val()` correctly handles negative integer strings: `Val("-1")` returns `-1`. Negative sentinel values stored as strings in buffers are safe.
- Integer negation works correctly in bitwise expressions. The lowest-set-bit idiom `remaining & (-remaining)` works correctly in TSE SAL.

---

**Output conventions**

- Always use `Warn()` for output (not `Message()`), and always add `CopyToWinClip()` of the result string.

- `Warn()` line breaks: use `Chr(13)` embedded in the string. `Chr(10)` displays as a glyph.

---

**Buffers - the universal collection/lookup structure**

- All collection/lookup data stored in TSE temp buffers, one value per
  line, accessed via `GotoLine()` / `GetText()` / `KillToEol()` /
  `InsertText()`.

- Line replacement idiom: `BegLine()` + `KillToEol()` + `InsertText()`
  - **not** `DelLine`/`InsertText`/`AddLine` or `lReplace`.

- Sieve of Eratosthenes stored as buffer lines ("1"/"0"), with line
  `n+1` for number `n` (off-by-one is a recurring bug to watch).

- TSE easily handles 150,000+ lines in a buffer. "Out of memory" in a TSE SAL macro is **not** caused by buffer size - look for runaway loops or logic errors.

**Recursion**

  these over `PushPosition()`/`PopPosition()` for deep recursion.

-Error: 'Stack overflow in macrointerpreter'.

 Possible solution: Use PushLocation() and PopLocation() instead of PushPosition() and PopPosition().

### Example: Complete TSE SAL Macro

```sal
/*
 * Example TSE SAL macro demonstrating key features
 * Save as: example.s
 */

proc Main()
    integer i, count
    string filename[80], line[255]

    // Get filename from user
    filename = AskFilename("Open file:", "*.txt")

    if filename == ""
        Warn("No file selected")
        return
    endif

    // Load the file
    if not LoadBuffer(filename)
        Warn("Failed to load: ", filename)
        return
    endif

    // Count non-empty lines
    count = 0
    GotoLine(1)

    for i = 1 to NumLines()
        if CurrLineLen() > 0
            count = count + 1
        endif
        Down()
    endfor

    Warn("File has ", count, " non-empty lines")
end
```
